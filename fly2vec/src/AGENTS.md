# Fly2Vec 설계 참조 문서

> 이 파일은 Fly2Vec 구현 시 항상 참조해야 하는 설계 문서 목록입니다.
> 에이전트/개발자는 코드 작성 전 아래 문서를 확인하여 설계 의도에 맞게 구현합니다.

## 핵심 설계 문서

### 1. 통합 제안서 (원본 설계)
- **경로**: `../../2026-05-02-fly2vec-combined-proposal.md`
- **내용**: 전체 아키텍처, 3단계 진화(Node2Vec→GCN→R-GAT), 서버 내 검증-수정 루프, MCP 도구 명세, 데이터 흐름, Qdrant RAG, 기대 성과
- **참조 시점**: 새로운 기능 추가, 아키텍처 결정, MCP 도구 시그니처 확인 시

### 1-1. 1페이지 제안서 (교수 제출 원본)
- **경로**: `../../2026-05-02-fly2vec-proposal-1page.md`
- **내용**: 교수에게 제출한 1페이지 요약 — 문제 정의, 3단계 진화, 방법론, 아키텍처, 실험 결과, 기술 스택
- **참조 시점**: 보고서 작성, 발표 자료, 프로젝트 범위 확인 시

### 2. 상세 구현 설계안
- **경로**: `../docs/2026-05-02-fly2vec-implementation-design.md`
- **내용**: Phase별 구현 계획, 클래스 다이어그램, MCP 도구 상세 명세, Qdrant 컬렉션 스키마, LangGraph 노드/엣지 명세, Docker 서비스 구성
- **참조 시점**: 코드 구현, 테스트 작성, 클래스/함수 시그니처 결정 시

### 3. 데이터 증강 설계
- **경로**: `../docs/2026-05-02-swarm-data-augmentation-design.md`
- **내용**: 6단계 증강 파이프라인, 실 데이터 분석, 노드 피처 확장(10d), 엣지 5종, 이상 시나리오 6종
- **참조 시점**: augmentor.py 구현, R-GAT 피처 변경, 학습 데이터 생성 시

## 규칙 문서

- **RULES.md**: `../RULES.md` — 네이밍, 독립성, 테스트, 환경 변수, 문서화 규칙
- **구현 로그**: `../docs/2026-05-02-implementation-log.md` — 작업 이력

## 설계 원칙

1. **제안서가 최상위 설계** — MCP 도구 시그니처, 상태 필드, 에이전트 루프는 제안서 기준
2. **구현 설계안이 코드 명세** — 클래스명, 파일 경로, Docker 포트는 설계안 기준
3. **증강 설계가 데이터 명세** — 피처 차원, 엣지 타입, 시나리오 형식은 증강 설계 기준
4. **충돌 시 제안서 > 설계안 > 코드** 우선순위
